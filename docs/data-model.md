# BridgeTwinAI - Data Model

## PostgreSQL/PostGIS Database Schema

The database relies on PostgreSQL. PostGIS is utilized for storing spatial geometries (bridges' locations and spans).

### 1. `bridges` Table
Stores static and geospatial information about the bridges.
- `id` (UUID, Primary Key)
- `name` (String) - e.g., "Vashi Road Bridge", "Atal Setu", "Bandra-Worli Sea Link"
- `geometry` (Geometry/PostGIS Point or LineString) - Geospatial coordinates
- `length_m` (Float) - Total length in meters
- `built_year` (Integer)
- `material_type` (String) - e.g., Concrete, Steel
- `traffic_volume` (Integer) - Baseline traffic volume
- `created_at` (Timestamp)
- `updated_at` (Timestamp)

### 2. `sensors` Table
Stores the metadata for physical/simulated sensors placed on the bridges.
- `id` (UUID, Primary Key)
- `bridge_id` (UUID, Foreign Key -> `bridges.id`)
- `sensor_type` (String) - e.g., "accelerometer", "strain_gauge", "displacement"
- `local_x` (Float) - 3D model X coordinate offset
- `local_y` (Float) - 3D model Y coordinate offset
- `local_z` (Float) - 3D model Z coordinate offset
- `status` (String) - e.g., "active", "offline"

### 3. `sensor_readings` Table (Time-Series)
Stores the high-frequency telemetry from the simulation engine. *Should be partitioned by time using TimeScaleDB if possible.*
- `id` (UUID, Primary Key)
- `sensor_id` (UUID, Foreign Key -> `sensors.id`)
- `timestamp` (Timestamp with Time Zone, Indexed)
- `value` (Float) - The measured value
- `unit` (String) - e.g., "m/s²", "microstrain"

### 4. `structural_assessments` Table
Stores periodic or triggered AI health evaluations.
- `id` (UUID, Primary Key)
- `bridge_id` (UUID, Foreign Key -> `bridges.id`)
- `timestamp` (Timestamp with Time Zone)
- `health_score` (Float) - 0.0 to 1.0 representing structural integrity
- `anomaly_detected` (Boolean)
- `details` (JSONB) - Storing explainability details (SHAP values, contributing sensors)

### 5. `maintenance_recommendations` Table
Stores actionable insights generated by the recommendation engine.
- `id` (UUID, Primary Key)
- `assessment_id` (UUID, Foreign Key -> `structural_assessments.id`)
- `bridge_id` (UUID, Foreign Key -> `bridges.id`)
- `recommended_action` (String) - e.g., "Inspect Deck", "Check Cables"
- `priority` (String) - "Low", "Medium", "High", "Critical"
- `status` (String) - "Pending", "Acknowledged", "Completed"
- `created_at` (Timestamp)
